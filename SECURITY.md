# Security Policy

## Supported Versions

The supported versions of this project are actively maintained. Please refer to the [Releases](https://github.com/rajeshkanaka/OCR-Devnagari/releases) page for information about supported versions.

## Reporting a Vulnerability Privately

To report a vulnerability, please send an email to [security@rajeshkanaka.com](mailto:security@rajeshkanaka.com) with the details of the vulnerability.

## What to Include in a Report

When reporting a vulnerability, please include the following information:
- A summary of the vulnerability
- Steps to reproduce the issue
- The impact of the vulnerability
- Any potential exploit code, if available
- References to any related issues or CVEs

## Response Expectations

We aim to acknowledge receipt of your report within 48 hours and will provide a status update within 5 business days. The timeline for a fix will vary depending on the nature of the vulnerability and the complexity of the fix.

## Disclosure Policy

We follow a responsible disclosure policy. Upon identifying and addressing a vulnerability, we will notify affected users and take appropriate steps to mitigate the risk. Details of the vulnerability may be publicly disclosed after an appropriate fix is released and if necessary, in accordance with this policy.

## Scope

This security policy pertains to all code contributions to the OCR-Devnagari repository and any related services.

## Dependency and Model Security Guidance

Ensure that third-party libraries and models used within this project are up to date and obtained from trusted sources. Regularly review dependency security advisories to address known vulnerabilities.

## Secrets Handling

Never include sensitive information such as API keys, passwords, or credentials in this repository or within the project source code. Utilize environment variables or a secure vault service to manage such sensitive information securely.

## Data Privacy Considerations for OCR Inputs

All input data submitted for OCR processing must be handled in accordance with applicable data privacy laws and regulations. Users should avoid including personally identifiable information (PII) unless necessary for application functionality.

## Note

Please do not open public issues for reporting vulnerabilities. Use the private reporting method outlined above instead.
